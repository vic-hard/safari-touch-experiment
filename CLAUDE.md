## Состояние репозитория

На данный момент в репозитории есть только `PLAN.md` — кода нет ни строки. Всё ниже описывает
целевую структуру из плана; при создании файлов следуйте ей, а не придумывайте свою.
Рабочий язык документов и комментариев — русский (как в `PLAN.md`).

## Суть проекта

Одноразовый измерительный эксперимент, не продукт: выяснить на iPhone 15 / Safari два
независимых вопроса — (В1) отдаёт ли WebKit живую геометрию контактного пятна
(`radiusX`/`radiusY`, `width`/`height`) и различает ли она мягкие/резкие тапы; (В2) как
квантуется тайминг `pointerdown`/`touchstart` относительно кадров 60 Гц и годится ли он для
ритм-игры. Эталон сравнения — нативный Android-сбор проекта TouchLab и его
`docs/softness-filter.md` (ссылки в плане идут как «SF §N»); этого репозитория здесь нет,
числа берутся из плана.

Ключевое архитектурное следствие: **В2 не гейтится исходом В1**. Тайминговый стенд
(`timing.html`) строится независимо от того, оказалась ли геометрия константой. Пробник
`probe.html` (этап Э1) гейтит только площадную половину.

`Touch.force` на iPhone 15 заведомо равен 0 (3D Touch убран) — канал силы не проверяется и в
код не закладывается.

## Целевая структура и границы слоёв

```
server/server.py       статика + POST /upload, только stdlib (http.server)
web/index.html         выбор режима
web/probe.html         Э1: какие поля живые
web/timing.html        Э2: метки, кадры, метроном
web/collect.html       Э3: серия по протоколу
web/js/clock.js        калибровка часов, границы кадров
web/js/motion.js       акселерометр и гироскоп (протокол accel-probe)
web/js/recorder.js     единая запись событий обоих потоков
web/js/export.js       POST на сервер + скачивание файлом
web/js/log.js          лог на экране вместо Web Inspector
data/                  выгруженные сессии, один JSON на сессию
analysis/analyze_clock.py    A2, A3
analysis/analyze_timing.py   A4, A5, A6, A7, A8
analysis/analyze_area.py     A1, A10
analysis/analyze_features.py микросдвиг, наборы признаков, разделимость
analysis/analyze_motion.py   M1–M6, проба канала акселерометра
docs/protocol.md       протокол съёмки, заполняется после Э1
docs/findings.md       критерии A1–A10 → фактические числа
```

Два тулчейна не заводим: сервер и анализ — Python **только stdlib**, без pip и без Node.
Страницы — ванильный JS без сборки и без зависимостей (их негде ставить: съёмка идёт с
телефона через туннель).

## Запуск стенда

```powershell
python server/server.py                      # статика + POST /upload -> data/
cloudflared tunnel --url http://localhost:8000   # https-адрес для iPhone
python analysis/analyze_timing.py data/<session>.json
```

HTTPS обязателен (туннель, не LAN-адрес): снимает класс вопросов «почему тут не работает» и
нужен для `DeviceMotion`. При работе по LAN входящие соединения к дев-серверу блокирует
брандмауэр Windows — через туннель это не всплывает.

Web Inspector недоступен (нет macOS). Отладка — `js/log.js` на странице плюс POST сырых
данных; сырые поля события и есть результат эксперимента, смотреть их надо в файле.
Выгрузка всегда двумя путями сразу: POST на сервер + скачивание файлом в Files app —
повторить снятую серию в тех же условиях невозможно.

## Конвенции данных и измерений

- Формат сессии версионируется полем `format`, начинаем с `web-probe-0.1.0`; секции
  `meta` / `clock` / `frames` / `events`.
- Недоступное значение пишется явным `null` — не опускается и не заменяется умолчанием
  (конвенция TouchLab, критерий 33). Константа в канале записывается как есть: это честная
  запись, а не брак.
- Калибровка часов (`clock.js`) делается **первой**: без известной гранулярности
  `performance.now()` (ожидаемо ~1 мс) любой вывод о кадровом квантовании (16.7 мс)
  несостоятелен.
- Привязка DOWN к кадру считается как смещение от метки предыдущего `requestAnimationFrame`.
  **Обязательный контроль метода:** то же смещение считается для `pointermove` — move заведомо
  склеен с кадрами и обязан дать узкую полосу. Полоса у обоих или ни у одного — сначала чиним
  метод, потом делаем выводы.
- Оба потока (Touch и Pointer) пишутся в один журнал на одном элементе, но `preventDefault` и
  `touch-action` одного потока искажают другой: кроме совмещённой серии снимаются две
  контрольные по 20 тапов (только Touch, только Pointer), и при расхождении выводы строятся по
  одиночным.
- Метроном — Web Audio по `AudioContext.currentTime`, перевод в шкалу `performance.now()` через
  `getOutputTimestamp()`. Меряется **СКО отклонения, а не среднее**: постоянная задержка вывода
  звука сдвигает среднее и не влияет на разброс.
- Площадь: признак — **максимум** площади за контакт (не первый отсчёт); обучение на двух
  сериях, проверка на третьей отложенной; градации только мягко/резко. Результат выражается как
  «сколько мягких прошло / сколько резких отсеяно», абсолютные пороги с Android несопоставимы.
- Синтетический ввод (симулятор, скриптовые тапы) невалиден для измерения площади и тайминга.

## Как считается работа сделанной

Выводы делает скрипт по выгруженному JSON, а не наблюдение на экране (критерий A9). Всякий
результат кладётся в `docs/findings.md` как «критерий A1–A10 → фактическое число». Критерии
целиком перечислены в `PLAN.md` §3; этапы Э0–Э6 и порядок работ — §4 и §12.
