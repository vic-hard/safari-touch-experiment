# Safari Touch Experiment — стенд

Одноразовый измерительный эксперимент на iPhone 15 / Safari: В1 — отдаёт ли WebKit живую
геометрию контактного пятна, В2 — как квантуется тайминг DOWN.

**Съёмка проведена 16.09.2026, эксперимент закончен.**

| что | где |
|---|---|
| Результаты и ответы на оба вопроса | [docs/findings.md](docs/findings.md) |
| Как воспроизвести прогон | [docs/reproduce.md](docs/reproduce.md) |
| Выгруженные сессии и контрольные суммы | [data/manifest.txt](data/manifest.txt), `data/*.json` |
| Постановка, критерии, методика | [PLAN.md](PLAN.md) |
| Протокол съёмки | [docs/protocol.md](docs/protocol.md) |

Коротко: тайминг для ритм-игры пригоден — момент касания известен точнее кадра, и кадровая
сетка теряется на фоне человеческого разброса (33.7 мс против 4.91 мс). Площадь работает, но
вдвое слабее андроидной: мягкие проходят полностью, резких отсеивается 14 из 30 против 27 из
30 на Android — канал квантован ступенями и промежуточных значений не даёт.

Зависимостей нет: Python из стандартной библиотеки и ванильный JS без сборки.

## Запуск

```powershell
python server/server.py                          # статика web/ + POST /upload -> data/
cloudflared tunnel --url http://localhost:8000   # https-адрес для iPhone
```

Открыть на телефоне https-адрес из вывода `cloudflared`. **По LAN-адресу не работать:**
HTTPS снимает класс вопросов «почему тут не работает» и нужен для `DeviceMotion`, а входящие
соединения к дев-серверу из локальной сети блокирует брандмауэр Windows.

Проверка, что сервер жив: `http://localhost:8000/health` отвечает `{"ok": true}`.

## Безопасность

### Туннель делает сервер доступным всему интернету

`cloudflared tunnel` выдаёт публичный https-адрес: по нему на стенд заходит кто угодно, вне
зависимости от вашей сети. Адрес случайный и живёт только пока работает процесс, но секретом
он не является — у всех, кому вы его дали, доступ сохраняется до остановки туннеля.

**Правило: туннель поднимается на время съёмки и гасится сразу после.**

### У сервера нет аутентификации

Это одноразовый измерительный стенд, а не сервис. Кто знает адрес — тот может писать файлы в
`data/`. Что ограничивает ущерб:

- принимается только `POST /upload`, только корректный JSON, не больше 64 МБ;
- имя файла собирается из метаданных и санитизируется, выход за `data/` невозможен;
- существующие файлы не перезаписываются — снятую серию затереть нельзя;
- раздача ограничена каталогом `web/`.

Чего это не отменяет: диск можно забить мусорными сессиями, а страницы стенда увидит любой,
кто получил ссылку. Для съёмки на час это приемлемо, для постоянно поднятого сервиса — нет.

### Что лежит в выгруженных данных

Если выкладываете проект в открытый репозиторий вместе с `data/`, вместе с ним публикуются:

| что | пример |
|---|---|
| версия iOS и параметры устройства | `iOS 18.7.5`, экран 393×852, `devicePixelRatio` 3, 4 ядра |
| язык интерфейса | `ru` |
| метка участника и номер серии | `p1`, `1` |
| заряд и режим энергосбережения | `82`, `off` |
| свободные заметки — ваш текст как есть | то, что набрано в поле «Заметки» |
| время съёмки с точностью до секунды | `2026-09-16T08:18:59.704Z` |
| координаты тапов | `(197, 254)` — внутри фиксированной зоны |

Чего в данных **нет**: учётных данных, токенов, геолокации, имён, адресов, содержимого экрана
и любого текстового ввода. Координаты относятся к размеченному прямоугольнику в середине
экрана, а не к клавиатуре, поэтому восстановить по ним что-либо нельзя.

Отдельно стоит решить про поле «заметки»: туда попадает произвольный текст, который вы
вводите перед серией, и он уходит в каждую сессию и в `data/manifest.txt`.

Данные — единственное, чем подтверждается отчёт: без них `docs/findings.md` остаётся набором
утверждений на слово. Поэтому по умолчанию их стоит публиковать вместе с кодом, а решение
принимать осознанно, а не по умолчанию в обе стороны.

## Порядок работ

| шаг | что делать |
|---|---|
| Э0 | поднять сервер и туннель, открыть страницу на телефоне, снять любую короткую серию и убедиться, что JSON лёг в `data/` |
| Э1 | `probe.html`: 20 тапов (10 мягких, 10 резких) → `analyze_area.py` → **ответ на В1** |
| — | записать исход Э1 в `docs/findings.md` и только потом решать, строится ли площадная половина |
| Э2 | `timing.html`: проверить, что метроном звучит, часы откалиброваны, кадры пишутся |
| Э3–Э4 | `collect.html`: серии по протоколу из `docs/protocol.md`, 3 захода в разное время |
| Э5 | скрипты анализа → числа в `docs/findings.md` |

Э2 строится в любом случае: В2 от исхода Э1 не зависит.

## Режимы страниц

- `index.html` — метаданные участника и выбор режима. Метаданные держатся в `localStorage`
  и подставляются во все режимы.
- `probe.html` — Э1, все поля обоих потоков на экране плюс серия из 20 тапов.
- `timing.html` — Э2, калибровка часов, границы кадров, метроном, живые гистограммы смещения.
- `collect.html` — Э3, съёмка по протоколу: метроном, свободные тапы, площадь, две
  контрольные серии по одному потоку.

## Анализ

```powershell
python analysis/analyze_clock.py  data/<session>.json          # A2, A3
python analysis/analyze_timing.py data/<session>.json          # A4-A8
python analysis/analyze_area.py   data/s1.json data/s2.json data/s3.json   # A1, A10
```

У каждого скрипта есть `--csv <файл>` для выгрузки подробностей. `analyze_area.py` по
умолчанию считает отложенной последнюю серию из списка, иначе `--holdout <файл>`.

Выводы делает скрипт по выгруженному JSON, а не наблюдение на экране (критерий A9). Цифры на
страницах нужны только чтобы заметить брак съёмки на месте.

Точные команды для каждого критерия, вместе с ожидаемыми числами, — в
[docs/reproduce.md](docs/reproduce.md).

## Отладка без Web Inspector

Web Inspector требует macOS, его не будет. Вместо него — лог прямо на странице (`js/log.js`,
туда же перехватываются ошибки) и POST сырых данных на ноутбук. Сырые поля события и есть
результат эксперимента, смотреть их надо в файле.

Выгрузка всегда идёт двумя путями сразу: POST на сервер и скачивание файлом в Files app.
Повторить снятую серию в тех же условиях невозможно, поэтому страховка обязательна.

## Чего делать нельзя

- **Синтетический ввод.** Симулятор iOS и скриптовые тапы невалидны и для площади, и для
  тайминга (PLAN §8) — по той же причине, по которой в TouchLab запрещён `adb shell input`.
- **Снимать серии при заряде ниже 50%** и не фиксировать режим энергосбережения: Low Power
  Mode срезает частоту обновления.
- **Считать константу браком.** Константа в канале записывается как есть; это честная
  запись и нормальный отрицательный результат.
- **Уводить страницу из фокуса посреди серии.** `requestAnimationFrame` при этом встаёт, и
  привязка событий к кадрам (A4) перестаёт что-либо значить. Сторож кадров пишет в лог
  «кадры не идут», а `analyze_timing.py` отказывается считать A4 по такой серии.

## Формат данных

Один JSON на сессию, версия в поле `format` (`web-probe-0.1.0`), секции `meta` / `clock` /
`frames` / `events` / `metronome`. Недоступное значение пишется явным `null`, а не
опускается и не заменяется умолчанием. Подробности — PLAN §9.
